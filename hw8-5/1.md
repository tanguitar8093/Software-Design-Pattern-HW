# Bot 模組：元件分工與錄音流程

可以把它們想成三種角色：Trigger 辨認「發生什麼事」；Action 負責「實際做什麼」；Guard 判斷「現在能不能轉移」。App 層不需要逐一呼叫它們；v1 是由社群產生事件、通知 `Bot.onEvent()`，再由 Bot 找出目前狀態並執行對應反應或轉移。[事件入口 (line 36)](v1/bot/bot.py) · [組裝位置 (line 56)](v1/bot/facade.py)

## Trigger：辨認事件

1. **`VoiceSpokenTrigger`**：有人在廣播中說話了嗎？若 Bot 正在 Recording，就交給 AddVoiceToRecordingSessionAction，把這句話存進本次錄音；它本身不負責輸出重播。[接線 (line 256)](v1/bot/facade.py)

2. **`MessageFromMemberTrigger`**：聊天室來了一則不是 Bot 自己發的訊息嗎？有就讓目前的 Default 或 Interacting 回覆下一句輪播訊息，不必有 @bot。「大家早安」也會得到回覆；MentionsBotTrigger 則留給確實要求 @bot 的答題等情境。[判斷條件 (line 28)](v1/bot/triggers/triggers.py) · [輪播接線 (line 218)](v1/bot/facade.py)

3. **`PostCreatedTrigger`**：論壇有人發新貼文了嗎？有就依目前是 Default 還是 Interacting，交給各自的 CommentPostAction：前者留言 Nice post、標記作者；後者留言 How do you guys think about it?、標記在線成員。[接線 (line 240)](v1/bot/facade.py)

## Action：執行動作

1. **`NoopAction`**：這個進場、離場位置需要一個 Action，但此時不用做事；呼叫後直接結束。[程式 (line 4)](v1/bot/actions/composite.py)

2. **`SetRecorderAction`**：有人成功下 record @bot 後，記下「下指令的人是誰」到 Bot.recorderId。後續換講者廣播也不會換掉錄音者；stop-recording 的權限和重播要標記誰，都會用到這個身分。[轉移接線 (line 165)](v1/bot/facade.py) · [程式 (line 55)](v1/bot/actions/concrete.py)

3. **`AddVoiceToRecordingSessionAction`**：接到錄音中的語音事件後，從事件取出講者和內容，呼叫 `RecordingSession.addVoice()` 暫存。等講者停止廣播、離開 Recording 時，才由離場行為產生 Record Replay 並傳到聊天室。[程式 (line 84)](v1/bot/actions/concrete.py) · [離場接線 (line 75)](v1/bot/facade.py)

4. **`ResetReplyCycleAction`**：每次進入 Default 或 Interacting，把該狀態的輪播索引歸零。下一則成員訊息來時，getNextReplyMessage() 就會拿第一句。[程式 (line 12)](v1/bot/actions/concrete.py) · [進場接線 (line 73)](v1/bot/facade.py)

5. **`AnnounceGameResultAction`**：一進 ThanksForJoining，向遊戲物件取得贏家，再問 Bot「現在有人廣播嗎？」有人就發聊天訊息，沒人就用語音公布；最後記下進場時間 enteredAt，供 20 秒後的判斷使用。[程式 (line 113)](v1/bot/actions/concrete.py)

6. **`CarryGameToThanksForJoiningAction`**：Questioning 因答完或超時要轉到 ThanksForJoining 時，把同一個遊戲物件的參照交給感謝參與狀態，讓它能讀取分數和贏家。這裡是傳參照，不是重新開一場遊戲。[程式 (line 104)](v1/bot/actions/concrete.py) · [兩條轉移 (line 105)](v1/bot/facade.py)

## Guard：限制轉移

**`SubstateActiveGuard`**：收到時間流逝事件時，外層只知道 Bot 在「知識王」；它再看知識王裡面是不是已經到了 ThanksForJoining。只有是，而且 enteredAt 起已過 20 秒，才准從知識王回 Normal；還在 Questioning 就不准走這條路。[Guard (line 85)](v1/bot/guards/concrete.py) · [轉移接線 (line 188)](v1/bot/facade.py)

## Trigger：程式碼執行順序

### 1. VoiceSpokenTrigger（錄音）

假設下 record 時還沒有人廣播：

1. **開始錄音**：`Member.sendMessage("record", ["bot"])` → `ChatRoom.postMessage()` → 發出 MessagePostedEvent → `Bot.onEvent()` → `rootFsm.fire()` → 命中 record 轉移 → SetRecorderAction 記下錄音者 → 進入 Waiting。[指令接線 (line 165)](v1/bot/facade.py)

2. **開始廣播**：`Member.startBroadcast()` → `Broadcast.start()` → 發出 BroadcastStartedEvent → `Bot.onEvent()` → `rootFsm.fire()` → 內層 `recordFsm.fire()` → Waiting 轉到 Recording → CreateRecordingSessionAction 建立空的 session。[狀態接線 (line 92)](v1/bot/facade.py)

3. **逐句收音**：`Member.speak()` → `Broadcast.speak()` → 發出 VoiceSpokenEvent → `Bot.onEvent()` → 找到目前狀態 Recording → `InternalReaction.isApplicable()` → `VoiceSpokenTrigger.isTriggeredBy()` → `AddVoiceToRecordingSessionAction.execute()` → `RecordingSession.addVoice()` 存下這句話 → 回到 `Bot.onEvent()` 執行 `rootFsm.fire()`；這個語音事件沒有造成狀態轉移，處理結束。每說一句，就重跑一次這段。[事件處理 (line 36)](v1/bot/bot.py) · [存入語音 (line 84)](v1/bot/actions/concrete.py)

4. **停止廣播並回放**：`Member.stopBroadcast()` → `Broadcast.stop()` → 發出 BroadcastStoppedEvent → `Bot.onEvent()` → `rootFsm.fire()` → `recordFsm.fire()` → 命中 Recording → Waiting → 先執行 `Recording.onExit()` → FlushRecordReplayAction 產生重播、透過 Bot 傳到聊天室、清掉 session → 最後進入 Waiting。[轉移接線 (line 97)](v1/bot/facade.py) · [回放程式 (line 34)](v1/bot/actions/concrete.py)

### 2. MessageFromMemberTrigger（聊天室輪播）

以下以 Bot 處於 `Default`、成員送出「大家早安」為例：

1. **發出事件**：`Member.sendMessage()` → `ChatRoom.postMessage()` → `EventPublisher.notify(MessagePostedEvent)` → `Bot.onEvent()`。[事件來源（L30）](v1/community/community.py)、[事件派送（L18）](v1/community/channels.py)

2. **判斷並回覆**：`Bot._getActiveLeafState()` 取得 `Default` → `InternalReaction.isApplicable()` → `MessageFromMemberTrigger.isTriggeredBy()` 確認作者不是 `bot`（不檢查 `@bot`）→ `SendChatMessageAction.execute()` → `Default.getNextReplyMessage()` 取出並推進輪播 → `Bot.replyChatMessage()` → `WaterCommunity.postBotReply()` → `ChatRoom.postMessage()`。Bot 的回覆也會產生事件，但作者是 `bot`，不會再命中此 Trigger。[輪播接線（L218）](v1/bot/facade.py)、[Trigger（L35）](v1/bot/triggers/triggers.py)、[回覆動作（L143）](v1/bot/actions/concrete.py)

3. **檢查轉移**：回到原本的 `Bot.onEvent()` → `rootFsm.fire()`；一般聊天不轉移，這次處理結束。如果同一則訊息也是合法指令，則**先輪播，後處理指令轉移**。`Interacting` 的流程相同，但使用自己的輪播文字。[Bot 事件順序（L36）](v1/bot/bot.py)

### 3. PostCreatedTrigger（論壇貼文）

以下以 Bot 處於 `Default`、成員發布貼文為例：

1. **發出事件**：`Member.publishPost()` → `Forum.createPost()` 儲存貼文 → `EventPublisher.notify(PostCreatedEvent)` → `Bot.onEvent()`。[事件來源（L33）](v1/community/community.py)、[論壇事件（L49）](v1/community/channels.py)

2. **判斷並留言**：`Bot._getActiveLeafState()` 取得 `Default` → `InternalReaction.isApplicable()` → `PostCreatedTrigger.isTriggeredBy()` → `CommentPostAction.execute()` → `Bot.commentPost()` → `WaterCommunity.postBotComment()` → `Forum.addComment()`，留言 `Nice post`、標記發文者。在 `Interacting` 則改用另一段留言並標記在線成員。[兩條接線（L240）](v1/bot/facade.py)、[留言動作（L23）](v1/bot/actions/concrete.py)

3. **結束**：留言會發出 `CommentAddedEvent`，不是 `PostCreatedEvent`，因此不會再次留言；回到原事件的 `Bot.onEvent()` → `rootFsm.fire()`，沒有貼文轉移，維持原狀態。[論壇留言（L55）](v1/community/channels.py)、[事件順序（L36）](v1/bot/bot.py)

## Action：程式碼執行順序

### 1. NoopAction（不用做事的進出場）

1. **被呼叫**：例如 `Waiting` 收到 `BroadcastStartedEvent`、FSM 命中 `Waiting → Recording` 時，先呼叫 `Waiting.onExit()` → `NoopAction.execute()`。[狀態接線（L92）](v1/bot/facade.py)、[FSM 順序（L109）](v1/fsm/core.py)

2. **直接返回**：`execute()` 內只有 `pass`；FSM 繼續轉到 `Recording`，再執行它的進場 Action。`NoopAction` 不產生事件，也不改資料。[程式（L4）](v1/bot/actions/composite.py)

### 2. SetRecorderAction（記下錄音者）

1. **指令通過**：成員發 `record @bot` → `Bot.onEvent()` → `rootFsm.fire()` → `CommandTrigger("record")` 和 `QuotaAvailableGuard` 成立，開始 `Normal → Record` 轉移。若在正常子狀態，會先有輪播回覆。[轉移接線（L165）](v1/bot/facade.py)

2. **執行 Action**：`CompositeAction.execute()` 先執行 `DeductQuotaAction` 扣 3 額度，再執行 `SetRecorderAction.execute(event)` → `event.getSourceId()` → 寫入 `Bot.recorderId`。[Action 順序（L170）](v1/bot/facade.py)、[程式（L55）](v1/bot/actions/concrete.py)

3. **接著進場**：FSM 進入 `recordFsm`，按是否有人廣播選 `Waiting` 或 `Recording`；後續只有 `recorderId` 相符的人能下 `stop-recording`。[初始子狀態（L92）](v1/bot/facade.py)、[錄音者 Guard（L73）](v1/bot/guards/concrete.py)

### 3. AddVoiceToRecordingSessionAction（存入一句語音）

1. **語音到來**：`Member.speak()` → `Broadcast.speak()` → `VoiceSpokenEvent` → `Bot.onEvent()` → 目前子狀態是 `Recording`，且 `VoiceSpokenTrigger` 命中。上方 Trigger 1 的完整流程、[原地反應接線（L256）](v1/bot/facade.py)

2. **執行 Action**：`AddVoiceToRecordingSessionAction.execute(event)` 確認事件類型且 `RecordingState.session` 非空 → 取 `event.voiceMessage` 的講者與內容 → `session.addVoice(VoiceMessage(...))`；若 session 不存在就直接返回。[程式（L84）](v1/bot/actions/concrete.py)、[錄音資料（L9）](v1/activities/recording.py)

3. **接著處理**：回到 `Bot.onEvent()` → `rootFsm.fire()`；本次語音不換狀態。等 `Recording.onExit()` 才由 `FlushRecordReplayAction` 輸出累積內容。[事件順序（L36）](v1/bot/bot.py)、[離場接線（L75）](v1/bot/facade.py)

### 4. ResetReplyCycleAction（重新從第一句輪播）

1. **進入狀態**：例如 `Default` 收到 `LoginEvent` 且在線人數達 10 → `normalFsm.fire()` 命中 `Default → Interacting` → `Interacting.onEnter()` → `ResetReplyCycleAction.execute()`。初次啟動或從錄音／知識王回到 Normal 時，選定子狀態的進場也走這個 Action。[切換與進場接線（L73、L79）](v1/bot/facade.py)

2. **索引歸零**：`Interacting.replyCycleIndex = 0`（進 `Default` 則重設 `Default` 的索引）。沒有立刻發訊息。[程式（L12）](v1/bot/actions/concrete.py)

3. **下一則訊息**：成員發聊天訊息 → `MessageFromMemberTrigger` 命中 → `SendChatMessageAction` 呼叫 `getNextReplyMessage()`，因此先回該狀態的第一句，然後索引加一。[輪播接線（L218）](v1/bot/facade.py)、[輪播狀態](v1/bot/states.py)

### 5. AnnounceGameResultAction（進場公布結果）

1. **進入感謝參與**：`Questioning` 最後一題答對或經過一小時 → `knowledgeKingFsm.fire()` 命中 `Questioning → ThanksForJoining` → 轉移 Action 先交接 `game` → `ThanksForJoining.onEnter()` → `AnnounceGameResultAction.execute()`。[兩條轉移（L105）](v1/bot/facade.py)、[進場接線（L78）](v1/bot/facade.py)

2. **公布結果**：`thanksForJoining.game.getWinner()` → 產生 `Tie!` 或 `The winner is <Id>` → `Bot.isBroadcasting()`；有人廣播就 `Bot.replyChatMessage()` → `WaterCommunity.postBotReply()`，否則 `Bot.broadcastVoice()` → `WaterCommunity.postBotVoice()`。[程式（L113）](v1/bot/actions/concrete.py)、[社群代理（L87～L93）](v1/community/community.py)

3. **記時間並等待**：公布方法返回後，`thanksForJoining.enteredAt = Bot.getCurrentTime()`。之後 `WaterCommunity.elapseTime()` 發出 `TimeElapsedEvent` → `SubstateActiveGuard` 和 20 秒的 `DurationElapsedGuard` 都成立，才回 `Normal`。[時間寫入（L129）](v1/bot/actions/concrete.py)、[20 秒轉移（L190）](v1/bot/facade.py)

### 6. CarryGameToThanksForJoiningAction（交接遊戲）

1. **選中轉移**：`Questioning` 最後一題答對、且有標記 Bot 時，`MentionsBotTrigger`／答題 Guard 命中；或者 `TimeElapsedEvent` 超過一小時，命中另一條 `Questioning → ThanksForJoining`。[兩條轉移（L105）](v1/bot/facade.py)

2. **先離場再交接**：`knowledgeKingFsm.fire()` → `Questioning.onExit()` → 轉移 Action；答完時先由 `SendChatMessageAction` 發送 `Congrats!`，再呼叫 `CarryGameToThanksForJoiningAction.execute()`，超時時直接呼叫它 → `thanksForJoining.game = questioning.game`（同一個參照）。[FSM 轉移順序（L109）](v1/fsm/core.py)、[交接程式（L104）](v1/bot/actions/concrete.py)

3. **接著公布**：FSM 設 `currentState = ThanksForJoining` → `ThanksForJoining.onEnter()` → `AnnounceGameResultAction` 從剛交接的遊戲讀取結果並公布。[進場接線（L78）](v1/bot/facade.py)

## 接 App 層時記得

給你接 App 層時最有用的一句話是：App 讓成員對 WaterCommunity 做操作；社群發事件給 Bot；Bot 依當前狀態選擇反應，再透過社群發訊息、留言或語音。另有一處文件與 v1 不一致，值得以 v1 為準：舊的 [BotFacade 差異說明（第 77 行）](../hw8-4/2/oodv4-6-botfacade-diff.md) 寫「先 fire() 再原地反應」，但目前 [`Bot.onEvent()` (line 36)](v1/bot/bot.py) 是先原地反應、再狀態轉移；這才符合 README 裡「king @bot 先輪播回覆，再進知識王」的例子。
