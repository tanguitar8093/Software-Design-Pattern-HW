# Rule 1 - `/tasks` 產施工圖前必須讀齊已存在的設計圖

- Level: `MUST`
- 產出 `tasks.md` 前，必須讀取同 package 已存在的設計圖，不得只靠 `testplan.md` 展開切片。已存在才讀，缺檔不捏造、不重做 system-analyze。
- 必讀清單（檔在才讀）：`spec.md`、`plan.md`、`testplan.md`、`system-analyze/technical-research.md`、`system-analyze/data-plan.md`、`system-analyze/DDL.md`、`system-analyze/api-plan.md`、`system-analyze/ui-plan.md`，以及 `system-analyze/ui/` 下的 HTML／CSS 雛形。
- 現行 `app/config/schema.sql`（若 repo 有）必須拿來對 `DDL.md`／`plan.md` 專案結構，判斷有沒有尚未落地的表或升級。
- `tasks.md` 開頭「輸入文件」必須列出本輪實際讀過的上述檔案。

## Good Example

- 這個例子是好的，因為施工圖進場先對齊資料與畫面設計圖。

```md
讀取：spec.md、plan.md、testplan.md、
technical-research.md、data-plan.md、DDL.md、
api-plan.md、ui-plan.md、ui/create.html、ui/preview.html
再對 app/config/schema.sql
```

## Bad Example

- 這個例子是壞的，因為只拿 testplan 展開，設計圖當選讀或沒讀。

```md
只讀 spec.md、plan.md、testplan.md、api-plan.md、ui-plan.md
跳過 DDL.md 與 ui/*.html
```

# Rule 2 - 設計圖上的 schema 增量必須編成 Foundational 工單

- Level: `MUST`
- 若 `DDL.md` 或 `plan.md` 專案結構出現相對現行 `schema.sql` 的增量（新表、`ALTER`、`schema_metadata` 升版、`migrations/`），Foundational **必須**有一則任務落地 `app/config/schema.sql`（及計畫中的升級腳本／version），必讀 `DDL.md`。
- 該則不得用測試 fixture 的 `CREATE TABLE IF NOT EXISTS` 代替正式 schema。Fixture 仍可插入列，但表結構以 schema／migration 為準。
- 該則仍不得偷做某個 User Story 的預覽、確認或畫面行為。
- 若 DDL 與現行 `schema.sql` 已一致、或本包無 DB／無 `DDL.md`，不要為了對稱空出 schema 任務。

## Good Example

- 這個例子是好的，因為新 draft 表先入 schema，再給 fixture 插資料。

```md
## Phase 2: 基礎前置（Foundational）
- [ ] T003 將 DDL 增量同步到 `app/config/schema.sql`（creation draft 表與加班主鍵自動編號），必要時補 v2→v3 升級
  - 必讀（Must Read）:
    - `system-analyze/DDL.md`
    - `plan.md` -> `### 原始碼（儲存庫根目錄）`
    - `app/config/schema.sql`
```

## Bad Example

- 這個例子是壞的，因為設計圖有新表，工單卻只準備 fixture。

```md
- [ ] T003 沿用 fixture 載入器，補齊 FX-CREATE-DRAFT
  - 原因（Why）: draft 用 fixture 插入，不呼叫尚未存在的 creation API
（GREEN 時在測具裡 CREATE TABLE IF NOT EXISTS）
```

# Rule 3 - 畫面雛形必須掛上前端施工任務

- Level: `MUST`
- 若存在 `system-analyze/ui/*.html`，對應頁面的 `[TDD-GREEN]` 與 `[ACCEPTANCE-GATE]` 必讀必須列出該雛形檔（可連同 `ui-plan.md` 頁面標題）。
- `[TDD-RED]`／`[TDD-ALIGN]` 至少要有 testplan 案例；雛形可放選讀。REFACTOR 不強制重列雛形。
- 沒有 `system-analyze/ui/` 時，維持 `ui-plan.md` 頁面標題即可，不得編造 HTML 路徑。

## Good Example

- 這個例子是好的，因為 GREEN 照雛形施工。

```md
- [ ] T024 [US1] [SLICE FE-E2E-001B] [TDD-GREEN] …
  - 必讀（Must Read）:
    - `testplan.md` -> `### FE-E2E-001B - 新增頁可送出遠峰範例並看到預覽`
    - `testplan.md` -> `### BE-API-001C - …`
    - `system-analyze/ui-plan.md` -> `### 頁面：新增預覽（P-PREVIEW）`
    - `system-analyze/ui/preview.html`
```

## Bad Example

- 這個例子是壞的，因為有雛形卻只掛 ui-plan 標題。

```md
- [ ] T024 [TDD-GREEN]
  - 選讀（Optional）:
    - `system-analyze/ui-plan.md` -> `### 頁面：新增預覽（P-PREVIEW）`
```
