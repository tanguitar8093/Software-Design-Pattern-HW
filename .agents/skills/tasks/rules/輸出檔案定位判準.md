# Rule 1 - 最終 tasks 必須寫到固定路徑

- Level: `MUST`
- `/tasks` 的最終產物路徑固定為 `specs/<NNN-plan-package>/tasks.md`。
- 不可寫入 `specs/<NNN-plan-package>/task-plan/`，也不可再產出 `task-backend.md`、`task-frontend.md`、`task-integration.md`。
- 不可把完成稿只留在聊天訊息或任意檔名中。

## Good Example

- 這個例子是好的，因為輸出與同 package 的 `spec.md`、`testplan.md` 並列。

```text
specs/001-overtime-correction/tasks.md
```

## Bad Example

- 這個例子是壞的，因為又拆成三檔。

```text
specs/001-overtime-correction/task-plan/task-backend.md
specs/001-overtime-correction/task-plan/task-frontend.md
specs/001-overtime-correction/task-plan/task-integration.md
```

# Rule 2 - `plan-package` 必須與上游 testplan 目錄對齊

- Level: `MUST`
- `plan-package` 必須沿用同功能的 `specs/<NNN-plan-package>/` 目錄名。
- 若使用者已指定既有 package，應寫入該 package，不可另開平行目錄。
- 同 package 必須已有 `testplan.md`；沒有就停止，請先 `/testplan`。

## Good Example

- 這個例子是好的，因為 tasks 與 testplan 落在同一 package。

```text
specs/001-overtime-correction/testplan.md
specs/001-overtime-correction/tasks.md
```

## Bad Example

- 這個例子是壞的，因為任務清單與測試計畫分散。

```text
specs/001-overtime-correction/testplan.md
specs/002-tasks-only/tasks.md
```

# Rule 3 - 標題與表頭必須對齊固定契約

- Level: `MUST`
- H1 固定為 `# 任務清單：{{FEATURE_TITLE}}`，功能中文名與同 package 的 `spec.md` 對齊。
- 表頭固定三欄、分行書寫：`**功能分支**:`、`**規格目錄**:`、`**輸入文件**:`。
- 功能分支值必須以 inline code 包住，且與所在 `plan-package` 相同。
- 規格目錄值必須是 `specs/<plan-package>`。
- 不可再使用 `Feature Directory`、`Input Documents` 當表頭。

## Good Example

- 這個例子是好的，因為表頭可對回目錄。

```md
# 任務清單：加班資料與計薪方式更正功能

**功能分支**: `001-overtime-correction`

**規格目錄**: `specs/001-overtime-correction`

**輸入文件**:
- `spec.md`
- `testplan.md`
```

## Bad Example

- 這個例子是壞的，因為沿用英文表頭或舊三檔標題。

```md
# Task Plan

**Feature Directory**: specs/001-overtime-correction
**Input Documents**: spec.md, e2e-test-plan.md
```
