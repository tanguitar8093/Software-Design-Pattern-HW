# Rule 1 - 每個契約案例必須有固定欄位與穩定識別

- Level: `MUST`
- `api-plan.md` 的「可機械驗證契約」必須是合法 JSON，頂層包含 `version` 與 `contracts`。
- 每個契約案例必須包含 `contract_id`、`user_story`、`method`、`path`、`status`、`request`、`response`。
- `contract_id` 必須在檔內唯一且穩定；method、path 與 status 必須能對到同檔人工可讀的 Endpoint 與 Responses。
- 每個 Responses 標題與測試規劃資料列都必須明列一個 `contract_id`；人工可讀案例與可機械驗證契約必須雙向一一對應，不得只檢查「機械契約能找到人工段落」。
- 不得宣告 `required_evidence` 或預猜 testplan 案例 ID；後續 `testplan.md` 與 `tasks.md` 以 `contract_id` 反向引用。

## Good Example

- 這個例子有可追溯案例識別與固定契約欄位。

```json
{
  "contract_id": "API-001-C1",
  "user_story": "US-1",
  "method": "POST",
  "path": "/albums",
  "status": 201,
  "request": {"type": "object"},
  "response": {"type": "object"}
}
```

## Bad Example

- 這個例子只留自由文字，後續無法可靠比對。

```text
建立相簿大概回成功，格式看上面的範例。
```

# Rule 2 - request 與 response 使用可驗證的 JSON Schema 子集

- Level: `MUST`
- `request` 與 `response` 必須是 JSON Schema 物件；本流程至少支援 `type`、`required`、`properties`、`items`、`enum`、`const` 與 `additionalProperties`。
- 無 request body 時使用 `{"type": "null"}`，不可省略欄位。
- 空物件 `{}` 會關閉所有形狀檢查，因此一律禁止；無 body 也不能用空物件代替 `{"type": "null"}`。
- Schema 只描述契約形狀與限制，不把每次執行都會變動的識別、日期或路徑寫成固定範例值。

## Good Example

- 這個例子允許識別值變動，但仍能驗證必要欄位與型別。

```json
{
  "type": "object",
  "required": ["id", "name"],
  "properties": {
    "id": {"type": "string"},
    "name": {"type": "string", "const": "旅行"}
  }
}
```

## Bad Example

- 這個例子把一次性的識別字當成唯一合法 response。

```json
{"id": "alb_only_this_run", "name": "旅行"}
```

# Rule 3 - 契約不宣告三層證據，只當 HTTP 契約來源

- Level: `MUST`
- 不得再寫 `required_evidence`，也不得使用 `backend-contract`、`frontend-mock`、`integration` 當契約欄位。
- PHPUnit 與 Playwright 都必須遵守同檔 method、path、status、request、response；需要改約時先回到 `api-plan.md`。
- 前端測試打真後端，不把契約當成 Mock fixture 來源。

## Good Example

- 這個例子是好的，因為契約只描述 HTTP 形狀，沒有三層證據欄。

```json
{
  "contract_id": "API-001-C1",
  "user_story": "US-1",
  "method": "POST",
  "path": "/albums",
  "status": 201,
  "request": {"type": "object"},
  "response": {"type": "object"}
}
```

## Bad Example

- 這個例子是壞的，因為又把前端 Mock 寫成必經證據。

```json
{"contract_id": "API-001-C1", "required_evidence": ["backend-contract", "frontend-mock", "integration"]}
```
