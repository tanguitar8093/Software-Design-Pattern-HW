# Rule 1 - 撰寫或重寫測試時以 3A 註解格式組織段落

- Level: `MUST`
- 當在真實測試檔中新增、修改或重寫單一測試時，應以 `# Arrange`、`# Act`、`# Assert` 作為段落註解，讓準備、執行與驗證邊界清楚可讀。
- 3A 註解的目的，是把測試中的 setup、觸發行為與結果驗證切開，讓讀者能快速看出目前測的是什麼行為。
- 不可把多個無關目的的程式碼混在同一段，讓段落名稱失去辨識價值。

## Good Example

- 這個例子是好的，因為測試內容依 3A 分段，讀者能立刻分辨準備、執行與驗證。

```py
def test_addition():
    # Arrange
    calc = Calculator()

    # Act
    calc.press("2")
    calc.press("+")
    calc.press("3")
    calc.press("=")

    # Assert
    assert calc.display == "5"
```

## Bad Example

- 這個例子是壞的，因為 setup、操作與 assertion 混在一起，無法快速辨識測試結構。

```py
def test_addition():
    calc = Calculator()
    calc.press("2")
    calc.press("+")
    calc.press("3")
    calc.press("=")
    assert calc.display == "5"
```

# Rule 2 - 每個 3A 段落只放對應性質的程式碼

- Level: `MUST`
- `Arrange` 只放建立測試物件、準備資料、設定前置狀態等程式碼。
- `Act` 只放本次要觀察的行為觸發；若需要多行呼叫才能構成同一次行為，可以集中放在同一段。
- `Assert` 只放驗證結果的 assertion，避免把新的狀態準備或額外行為夾帶進來。
- 不可在 `Assert` 段落才補前置資料，也不可在 `Arrange` 段落先偷跑主要行為，否則 3A 只剩表面註解。

## Good Example

- 這個例子是好的，因為清除前的狀態準備留在 `Arrange`，真正要觀察的清除動作留在 `Act`。

```py
def test_clear_resets_display():
    # Arrange
    calc = Calculator()
    calc.press("9")

    # Act
    calc.press("C")

    # Assert
    assert calc.display == "0"
```

## Bad Example

- 這個例子是壞的，因為它把要觀察的主要行為放進 `Arrange`，讓 `Act` 段落失真。

```py
def test_clear_resets_display():
    # Arrange
    calc = Calculator()
    calc.press("9")
    calc.press("C")

    # Assert
    assert calc.display == "0"
```

# Rule 3 - 不存在的段落應直接省略，不保留空 3A 註解

- Level: `MUST`
- 若某個測試不存在對應段落，應直接省略該註解，而不是留下空的 `# Arrange`、`# Act` 或 `# Assert`。
- 例如只有建構物件後直接驗證初始狀態的測試，可以只有 `Arrange` 與 `Assert`；像 smoke test 這種只有單一 assertion 的測試，可以只保留 `Assert`。
- 省略不存在的段落，是為了讓註解仍然反映真實結構，而不是機械地把 3A 填滿。

## Good Example

- 這個例子是好的，因為測試沒有獨立的 `Act`，所以直接省略，保留真實結構。

```py
def test_new_calculator_shows_zero():
    # Arrange
    calc = Calculator()

    # Assert
    assert calc.display == "0"
```

## Bad Example

- 這個例子是壞的，因為它為了湊齊 3A 保留空段落，讓註解失去資訊價值。

```py
def test_new_calculator_shows_zero():
    # Arrange
    calc = Calculator()

    # Act

    # Assert
    assert calc.display == "0"
```

# Rule 4 - 3A 註解語法必須跟隨測試語言，不可整份抄 Python `#`

- Level: `MUST`
- 3A 段落名稱固定為 `Arrange`、`Act`、`Assert`；註解語法跟隨測試檔語言：PHPUnit／Playwright／JavaScript／TypeScript 使用 `// Arrange`，Python 使用 `# Arrange`。
- 不可因為水球範例是 Python，就把 `# Arrange` 寫進 PHP 或 Playwright 測試。
- 空段落省略規則仍適用；只是註解前綴改成該語言的行註解。

## Good Example

- 這個例子是好的，因為 PHP 測試用 `//` 標出 3A。

```php
public function testPreviewReturnsBeforeAfter(): void
{
    // Arrange
    $this->loadFixture('FX-FARFENG-AUG08');

    // Act
    $response = $this->postJson('/overtime/preview', $payload);

    // Assert
    $response->assertOk();
}
```

## Bad Example

- 這個例子是壞的，因為 PHP 測試照抄 Python 的 `# Arrange`。

```php
public function testPreviewReturnsBeforeAfter(): void
{
    # Arrange
    $this->loadFixture('FX-FARFENG-AUG08');
    # Act
    $response = $this->postJson('/overtime/preview', $payload);
    # Assert
    $response->assertOk();
}
```
