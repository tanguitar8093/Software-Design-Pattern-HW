# Rule 1 - 最終憲法必須寫在專案根目錄固定路徑

- Level: `MUST`
- `/constitution` 的最終產物路徑固定為專案根目錄的 `constitution.md`（相對於 repo root）。
- 不可寫入 `.agents/`、`specs/`、各 skill 目錄，或其他任意路徑。
- 不可把完成稿只留在聊天訊息中而不寫入檔案。

## Good Example

- 這個例子是好的，因為輸出落在專案根目錄固定檔名。

```text
constitution.md
```

## Bad Example

- 這個例子是壞的，因為把憲法放進 skill 或 specs，定位錯誤。

```text
.agents/skills/constitution/constitution.md
specs/001-photo-albums/constitution.md
```

# Rule 2 - 無檔則新建、有檔則修訂

- Level: `MUST`
- 若專案根目錄不存在 `constitution.md`，本次 MUST 走「新建」：依樣板寫出完整初稿。
- 若檔案已存在，本次 MUST 走「修訂」：在既有內容上更新使用者指定或已收斂的章節，不得無故清空整份無關章節。
- 本 skill 是憲法的寫入方；「交付 skill 缺檔時警告後繼續」不適用於本 skill——本 skill 缺檔時應新建，而非跳過。

## Good Example

- 這個例子是好的，因為依檔案是否存在選擇正確模式。

```text
不存在 constitution.md → 新建完整初稿
已存在 constitution.md → 只修訂相關章節與 metadata
```

## Bad Example

- 這個例子是壞的，因為修訂時把整份檔覆寫成無關空殼，或缺檔時拒絕建立。

```text
已有完整憲法，卻用空白樣板整檔覆蓋
缺檔時回報「無憲法可讀」並停止，不建立
```

# Rule 3 - 本 skill 不得同步修改其他 skill 或 templates

- Level: `MUST`
- V1 完成條件只包含寫入／更新 `constitution.md` 與其 metadata。
- 禁止為了「憲法變更傳播」而修改其他交付 skill 的 `SKILL.md`、`rules/`、`templates/`，或專案內其他樣板。
- 相依流程之日後掛接（例如各 skill 先 READ 憲法）不在本 skill 職責內。

## Good Example

- 這個例子是好的，因為變更範圍僅限憲法本體。

```text
更新 constitution.md 的技術約束與版本 → 結束
```

## Bad Example

- 這個例子是壞的，因為順便改了其他 skill，超出改動邊界。

```text
更新 constitution.md 後，又去改 implement/SKILL.md 加上 READ 憲法
```

# Rule 4 - 標題與 metadata 必須使用中文固定欄位

- Level: `MUST`
- H1 固定為 `# 開發規範（憲法）：{{PROJECT_NAME}}`。
- 小標固定分行書寫，至少包含：`**建立日期**:`、`**最後修訂**:`、`**狀態**:`、`**版本**:`；日期為 `YYYY-MM-DD`；版本值以 inline code 包住（例如 `` `1.0.1` ``）。
- 不可使用英文 SpecKit 單行格式（例如 `Version | Ratified | Last Amended`），也不可加入「功能分支」欄（憲法為專案級，非單一 feature 產物）。

## Good Example

- 這個例子是好的，因為與專案其他 artifact 的中文 metadata 風格一致，且不含功能分支。

```md
# 開發規範（憲法）：Jochu Lv1 訓練專案

**建立日期**: 2026-07-29
**最後修訂**: 2026-07-29
**狀態**: 草稿
**版本**: `1.0.1`
```

## Bad Example

- 這個例子是壞的，因為混用英文治理列，並誤加功能分支。

```md
# Constitution

**Version**: 1.0.0 | **Ratified**: 2026-07-29 | **Last Amended**: 2026-07-29
**功能分支**: `001-photo-albums`
```
