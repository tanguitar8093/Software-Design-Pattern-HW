# Rule 1 - 僅可獨立到達的全頁算「頁面」，且掛在頁面設計之下

- Level: `MUST`
- 檔案必須有 `## 頁面設計`；其下每個全頁使用 `### 頁面：名稱（代號）`。
- 「頁面」只包含使用者可獨立到達的全頁／主畫面；Modal、Drawer、確認框、本機檔案選取器、頁內選目標清單等不算獨立頁。
- 附屬 UI 應寫進所屬頁的「操作 Flow」與「呈現內容」，不可升級成 `### 頁面：`。
- 導覽表只描述全頁之間的轉移。

## Good Example

- 這個例子是好的，因為建立表單留在主頁 Flow，沒有另開頁。

```md
## 頁面設計

### 頁面：主頁（Home）
#### 操作 Flow
使用者輸入名稱並確認建立（Modal／表單附屬本頁）
```

## Bad Example

- 這個例子是壞的，因為把 Modal 升格成頁面。

```md
### 頁面：建立相簿 Dialog（CreateAlbumModal）
```

# Rule 2 - 每個頁面必須展開編排、合約與狀態

- Level: `MUST`
- 每個 `### 頁面：名稱（代號）` 開頭必須標 `對應雛形檔案` 與 `進入條件`。
- 其後必須依序包含：`#### 職責`、`#### 頁面編排`、`#### 呈現內容`、`#### 操作 Flow`、`#### 狀態`、`#### 導覽`、`#### API 對應`。
- **職責**：條列此頁處理的 US／FR（可標入口／驗證端）。
- **頁面編排**：區塊空間關係（可用 Mermaid `flowchart`）；寫頂欄、主內容、空狀態區、Modal 覆蓋，不寫色票或字級。
- **呈現內容**：此頁顯示哪些資訊／區塊／空狀態（人機「看見什麼」）。
- **操作 Flow**：頁內使用者↔系統／API 的 Mermaid Sequence。
- **狀態**：表格欄位固定為 `狀態 ID`｜`觸發時間`｜`畫面文案`；畫面文案是測試要比對的字。
- **導覽**：表格列出操作 → 前往頁面。
- **API 對應**：表格列出使用者操作 → API → 說明；頁內需要的列表資料來源不可省略。

## Good Example

- 這個例子是好的，因為區塊齊全，且狀態有可斷言文案。

```md
### 頁面：主頁（Home）
- 對應雛形檔案：`ui/index.html`
- 進入條件：開啟應用預設入口
#### 職責
- **US-2**：依建立日期分組瀏覽相簿
#### 頁面編排
（頂欄 → 主內容 → 日期分組）
#### 呈現內容
- 應用標題：**相簿**
#### 操作 Flow
（含 GET /albums）
#### 狀態
| 狀態 ID | 觸發時間 | 畫面文案 |
| `home-empty` | `groups` 為空 | 標題「還沒有相簿」；說明「建立第一個相簿，開始整理照片。」 |
#### 導覽
| 操作 | 前往頁面 |
#### API 對應
| 載入主頁相簿列表 | `GET /albums` | … |
```

## Bad Example

- 這個例子是壞的，因為缺編排與狀態，且操作沒有 API 對應。

```md
### 頁面：主頁（Home）
#### 職責
- US-2
#### 導覽
| 返回 | 主頁 |
```

# Rule 3 - 視覺方向寫在計畫層；像素細節留給雛形 CSS

- Level: `MUST`
- `ui-plan.md` 必須有 `## 視覺方向`（風格來源、本次風格結論、視覺重點、審美原則）。
- 頁面「呈現內容」與「頁面編排」不寫色票、字級、圓角、間距數值或元件庫實作細節。
- 高保真觀感由 `ui/*.html` 與 CSS 承擔；不把 Figma 當成本 skill 產物。

## Good Example

- 這個例子是好的，因為計畫層寫方向與區塊，不把 hex 塞進呈現內容。

```md
## 視覺方向
- 本次風格結論：個人相簿整理工具。暖色紙感背景、大面積照片區塊。

#### 呈現內容
- 依 group_date 分組的相簿列表；項目含 name、photo_count
```

## Bad Example

- 這個例子是壞的，因為在呈現內容寫像素稿。

```md
#### 呈現內容
- 主色 #6C5CE7，卡片圓角 16px，標題用 Inter 24/Bold
```

# Rule 4 - 頁面總覽必須掛在頁面設計之下以串起導覽關係

- Level: `MUST`
- 在各頁展開之後，必須有 `### 頁面總覽（導覽關係）`，含導覽關係圖（Mermaid flowchart）與「頁面｜主要 US」表（可加雛形欄）。
- 總覽應與各頁導覽表一致，不可出現總覽有、內文無的頁面。

## Good Example

- 這個例子是好的，因為總覽與內文頁面一致。

```md
### 頁面總覽（導覽關係）
（flowchart：Home ↔ Album）
| 頁面 | 主要 US | 雛形 |
| 主頁 | US-2、US-3；入口承載 US-1 | `ui/index.html` |
```

## Bad Example

- 這個例子是壞的，因為總覽多出未展開的頁面。

```md
| 設定頁 | US-99 |
（全文沒有 ### 頁面：設定頁）
```
