## 上游輸入與規劃邊界

- **主要上游 artifacts**: `spec.md`、`plan.md`、`system-analyze/api-plan.md`、`system-analyze/ui-plan.md`
- **這份 testplan 的責任**: 承接已完成的 User Story、FR / NFR 與介面盤點，轉成可交接給 `/tasks` 的測試案例；之後由 `/implement` 執行。
- **這份 testplan 不負責**: 重新切系統介面、重新發明端點，或把 system-analyze 再做一次。
- **上游已盤點受測介面**:
  - 後台更正修改頁／預覽頁／既有月結報表（Playwright 打真執行期）
  - 加班更正 HTTP API（PHPUnit 打正式 HTTP）
- **測試棧**: 後端 Slice 用 PHPUnit 打正式 API；前端 Slice 用 Playwright 開 `http://localhost:8088` 打**實際後端**。不用 persistence／repository seam，不用前端契約 Mock。

## 本輪不納入測試的項目

- 新增帳號、角色或權限控管。
- 完整客戶設定模組、加班費倍率調整、獨立「重新產生月結」按鈕。
- 以契約 Mock 讓前端燈變綠；前端 Slice 必須打真 API。
- 直接測 Model／Repository internals（不建立 `BE-REPO-*`）。
- 連正式客戶資料庫。

## 案例分類與 TDD 關係

- **驗收旅程（Acceptance Journey）**: 驗證單一 User Story 的最終可用結果，必須列出依賴的 TDD 切片（Slice），等組成切片（Slice）全綠才跑，不當單輪紅燈。
- **TDD 切片（Slice）**: 一次只驗證一個 public seam 的一個主要行為；後端是 API HTTP，前端是 Playwright 真畫面。每個切片由 `/tasks` 展開成 `RED -> GREEN -> REFACTOR`。
- **全域 NFR 測試**: 只收納跨多個 User Story 的品質約束；故事專屬 NFR 留在該故事底下引用，不另開 Slice。
