# 專案循序圖

這份文件用 Mermaid 畫出整個 RPG 專案從建立軍隊到戰鬥結束的主要互動流程。

## 1. 主流程總覽

```mermaid
sequenceDiagram
    actor User as 使用者
    participant Main as main.py
    participant Factory as build_skills / SKILL_TYPES
    participant Unit as Unit
    participant Engine as RPG
    participant State as current_state: State
    participant Strategy as DecisionStrategy
    participant Action as Action
    participant Target as Target Unit
    participant Observer as DeathObserver

    User->>Main: 啟動程式並輸入軍隊資料

    alt 輸入 troop_size 快速建軍
        loop 建立英雄、隊友、敵人
            Main->>Unit: __init__(name, hp, mp, str, is_hero)
            Unit-->>Main: unit
            alt 英雄
                Main->>Strategy: 建立 HumanStrategy()
                Main->>Factory: build_skills(DEFAULT_HERO_SKILL_NAMES)
                Factory-->>Main: skills
            else 隊友或怪物
                Main->>Strategy: 建立 AIStrategy()
                Main->>Action: 建立 BasicAttack()
                Action-->>Main: basic attack
            end
        end
    else 逐行輸入軍隊資料
        loop 讀取每一筆 Unit 資料
            Main->>Unit: __init__(name, hp, mp, str, is_hero)
            alt 軍隊 1 的英雄
                Main->>Strategy: 建立 HumanStrategy()
            else 其他單位
                Main->>Strategy: 建立 AIStrategy()
            end
            Main->>Factory: build_skills(parts[4:])
            Factory-->>Main: skills
        end
    end

    Main->>Engine: RPG(t1_units, t2_units)
    Engine->>Unit: 設定 troop / enemy_troop / troop_id

    loop 直到其中一方全滅
        Engine->>Unit: 取出目前行動單位
        Engine->>State: on_round_begin(unit)

        alt 狀態阻止行動或單位已死亡
            State-->>Engine: can_act = false
            Engine->>State: countdown(unit)
        else 可以行動
            State-->>Engine: can_act = true
            Engine->>Strategy: select_action(unit)
            Strategy-->>Engine: action
            Engine->>Strategy: select_targets(unit, action, current_board)
            Strategy-->>Engine: targets
            Engine->>Action: execute(unit, targets)

            loop 依技能效果處理各 target
                alt 攻擊或法術
                    Action->>Target: cause_damage(...) / change_state(...)
                else 治療或附加效果
                    Action->>Target: heal(...) / attach(...)
                end

                opt 召喚技能
                    Action->>Unit: 建立 Slime 並加入 troop
                end

                opt target 死亡
                    Target->>Observer: notify observers
                    Observer-->>Target: on_unit_death(dead_unit)
                end
            end

            Engine->>State: countdown(unit)
        end
    end

    Engine-->>User: 輸出勝負結果
```

## 2. 回合內部細節

這張圖聚焦在單一回合內，讓 `State`、`Strategy`、`Command`、`Observer` 怎麼串起來更清楚。

```mermaid
sequenceDiagram
    participant Engine as RPG
    participant Unit as acting Unit
    participant State as State
    participant Strategy as HumanStrategy / AIStrategy
    participant Action as Action
    participant Target as target Unit
    participant Observer as attached observers

    Engine->>State: on_round_begin(unit)

    alt 石化等狀態使其不能行動
        State-->>Engine: false
        Engine->>State: countdown(unit)
    else 可行動
        State-->>Engine: true
        Engine->>Strategy: select_action(unit)
        Strategy-->>Engine: action
        Engine->>Strategy: select_targets(unit, action, current_board)
        Strategy-->>Engine: targets
        Engine->>Action: execute(unit, targets)

        alt 技能造成傷害
            Action->>Target: take_damage(...) / cause_damage(...)
            opt target.hp <= 0
                Target->>Observer: notify()
                loop 對每個 observer
                    Observer-->>Target: on_unit_death(dead_unit)
                end
            end
        else 技能改變狀態
            Action->>Target: change_state(new_state)
        else 技能附加觀察者
            Action->>Target: attach(observer)
        else 技能召喚單位
            Action->>Unit: 新增 Slime 到 troop
        end

        Engine->>State: countdown(unit)
    end
```

## 3. 圖中各參與者對應到的程式

- `Main`：負責讀取輸入、建立單位、指派策略與技能
- `RPG`：負責整體戰鬥流程控制
- `Unit`：核心實體，持有 state、strategy、skills、observers
- `State`：處理回合開始效果與狀態倒數
- `Strategy`：決定這回合用哪個技能、打誰
- `Action`：真正執行技能效果
- `Observer`：在死亡事件發生時觸發額外反應

## 4. 閱讀建議

如果你想搭配設計模式一起看，推薦順序是：

1. 先看主流程總覽，理解 `main -> RPG -> Unit`
2. 再看回合內部細節，理解 `State -> Strategy -> Action -> Observer`
3. 最後搭配 `docs/設計模式解析` 裡的各模式文件一起對照
