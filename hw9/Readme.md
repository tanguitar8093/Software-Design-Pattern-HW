你在一間全台最大的電商購物網站中任職技術顧問。公司因營收成長而擴建產品團隊，希望透過技術研發提供更體貼的購物體驗，例如：

## B. 基因演算法

### 什麼是最佳化演算法？

**最佳化演算法（Optimization Algorithm）** 用於在特定限制條件下，找到能最大化或最小化某個 **目標函數（Objective Function）** 的解。

例如：你帶著固定金額到超市，希望在有限預算內買到最多物品。

| 項目 | 對應內容 |
| --- | --- |
| 限制條件 | 錢包中的預算。 |
| 目標函數 | 買到的物品數量。 |
| 最佳化目標 | 最大化物品數量。 |

基因演算法以自然選擇與基因遺傳為比喻，透過「優勝劣汰」反覆改善答案。

> 基因演算法採用隨機與機率方法，**無法保證找到最佳解**。每次執行的結果可能不同；演化時間越長，越有機會接近最佳解。

### 核心概念

理解演算法時，需要將生物學的比喻對應到具體的程式行為。

| 名稱 | 英文 | 程式中的意義 |
| --- | --- | --- |
| 種群 | Population | 一群候選答案。 |
| 個體 | Individual | 一個候選答案。 |
| 基因 | Gene | 組成答案的基礎元素。 |
| 染色體 | Chromosome | 個體身上的一序列基因。 |
| 適應度 | Fitness | 衡量答案表現好壞的量化指標。 |
| 篩選 | Selection | 選出參與繁殖的父母個體。 |
| 交配 | Crossover | 依規則組合父母基因，產生後代。 |
| 變異 | Mutation | 改變後代的部分基因，增加多樣性。 |

### 1. 個體就是最佳化問題的候選答案

演算法在種群中尋找表現最好的個體。依問題不同，個體可能是整數、整數陣列，或某個領域中的物件。

| 問題／個體型態 | 個體代表的答案 | 基因 |
| --- | --- | --- |
| 商品推薦：`List<Product>` | 一份商品推薦清單。 | 單一 `Product`。 |
| 工廠生產排程：排程物件 | 一份生產排程。 | 依排程表示方式定義。 |
| 整數陣列：`int[]` | 一組整數。 | 單一整數 `int`。 |
| 整數：`int` | 一個整數。 | 二進位位元（bit），在 Java 中可用 `boolean` 表示 1 或 0。 |

### 2. 個體之間可以交配

交配是指：**創造一個新個體，讓它依某種規則遺傳父母的基因。**

適應度較好的個體通常較不容易被淘汰，演算法會讓這些個體配對，期望後代也有良好的表現。透過反覆篩選、交配與變異，逐步尋找更好的答案。

以商品推薦為例：共有六種產品 `[A, B, C, D, E, F]`，使用者喜歡 `A、C、E`。每個個體是 `List<Product>`，基因是 `Product`。

| 個體 | 適應度 |
| --- | ---: |
| `[A, B, C]` | 2 |
| `[C, E]` | 2 |
| `[D, E, F]` | 1 |
| `[B, F]` | 0 |

選擇適應度最好的 `[A, B, C]` 與 `[C, E]` 作為父母，可能產生：

| 後代 | 可能的適應度 |
| --- | ---: |
| `[A, B, C, E]` | 3 |
| `[A, C, E]` | 5 |

以上是原題的簡化示意，未提供具體的適應度計算公式。重點在於：後代繼承優秀父母的基因，因此有機會表現得更好。

### 演算法流程概覽

```text
初始化種群
    ↓
篩選 → 交配 → 變異
    ↑            │
    └─ 尚未終止 ─┘
                 ↓ 達到終止條件或迭代上限
       回傳最終種群中適應度最好的個體
```

原題的概念性虛擬程式碼：

```text
種群 = 初始化種群()

基因演算法(種群): 個體 {
    重複迭代一定的次數 {
        種群 = 基因篩選、交配、變異(種群)
    }
    回傳種群中最優秀的個體
}
```

### 3. 篩選（Selection）：優勝劣汰

從當前種群中選出一部分個體，作為下一代的父母。原則上，適應度較好的個體被選中的機率較高。

| 策略 | 說明 |
| --- | --- |
| 錦標賽篩選法（Tournament Selection） | 隨機選出部分個體進行比較，讓適應度最好的個體參與繁殖。 |
| 排序篩選法（Rank Selection） | 依適應度由高到低排序，再根據排名選取個體交配。 |

**原題範例：**

- 錦標賽：從原有個體隨機選取 2 個比較，再從剩餘個體選取 2 個比較，最後讓兩組各自的優勝者參與繁殖。
- 排序：四個個體的適應度依序為 `50、30、80、10`，排序後的個體編號為 `3、1、2、4`，再依排名進行抽選。

### 4. 交配（Crossover）：組合父母基因

將選中的個體依一定機率配對，依交配規則創造後代（Offspring），增加種群的多樣性（Diversity）。後代會擁有交換後的染色體。

| 策略 | 說明 |
| --- | --- |
| 一點交配（Single-Point Crossover） | 隨機選一個交配點，交換兩個個體在該點切分的基因片段。 |
| 雙點交配（Two-Point Crossover） | 隨機選兩個交配點，交換兩點之間的基因區間。 |
| 均勻交配（Uniform Crossover） | 每一個基因各有一半機率繼承自任一父母。 |

假設父母的染色體如下：

```text
Parent 1: 11010101
Parent 2: 00101110
```

原題提供的交配結果：

| 交配方式 | 交配點／規則 | Offspring 1 | Offspring 2 |
| --- | --- | --- | --- |
| 一點交配 | 第四個基因，索引值為 3。 | `11001110` | `00110101` |
| 雙點交配 | 第二與第七個基因，索引值為 1 與 6。 | `11101110` | `00010101` |
| 均勻交配 | 每個基因以 50% 機率繼承自任一父母。 | `11011111` | `00100100` |

### 5. 變異（Mutation）：增加基因多樣性

讓新生成的個體依一定機率變異，可採用隨機替換、反轉、位移等方式。

| 策略 | 原題說明 |
| --- | --- |
| 隨機替換（Random Replacement） | 隨機將染色體中的一個或多個基因替換成新的基因值。 |
| 反轉操作（Inversion Mutation） | 將染色體中一段連續的基因反轉。原題範例：`001011101` → `110100010`。 |

> 原題的「反轉操作」範例實際呈現的是逐位元取反，與基因序列順序反轉的描述不同；此處保留原例供對照。

### 6. 重複演化與取得結果

重複「篩選 → 交配 → 變異」，直到達到終止條件，或最大迭代次數（Maximum Number of Iterations）。最後，取出最終種群中適應度最好的個體，作為最佳化結果。

以下將原題混合語法的虛擬程式碼統一縮排，以便閱讀：

```text
Individual geneticAlgorithm(Population population) {
    Population currentPopulation = population

    for (i in 1..MAXIMUM_NUMBER_OF_ITERATIONS) {
        // 優勝劣汰：選出這一代中最優秀的一群個體作為父母
        Population parents = selection(currentPopulation)

        // 讓父母交配，產生新的一代
        Population offspring = crossover(parents)

        // 透過變異增加新一代的多樣性
        Population newPopulation = mutate(offspring)
        currentPopulation = newPopulation

        if (terminationCondition()) {
            break
        }
    }

    // 從最終種群中取得適應度最好的個體
    return findBestIndividual(currentPopulation)
}
```

## E. 測試情境 1：工廠生產排程

你在製造公司任職演算法工程師，需要安排機器與工人的時間，在最短時間內完成所需產品數量，滿足客戶需求並最小化生產成本。

- 可用資源：**2 台機器、4 名工人**。

### 任務

## F. 測試情境 2：購物網站推薦

根據客戶的預算、購物袋承重上限與產品類別喜好，產生一份購買推薦清單。

### 商品資料

| 產品 | 價格 | 重量 | 類別 |
| --- | ---: | ---: | :---: |
| 產品 1 | 100 元 | 2 公斤 | A |
| 產品 2 | 200 元 | 3 公斤 | A |
| 產品 3 | 150 元 | 5 公斤 | B |
| 產品 4 | 300 元 | 4 公斤 | B |
| 產品 5 | 180 元 | 6 公斤 | C |
| 產品 6 | 250 元 | 7 公斤 | C |

### 客戶喜好度（Preference）範例

系統會記錄每位客戶對不同產品類別的喜好度：

| 類別 | 喜好度 |
| --- | ---: |
| A | 80% |
| B | 60% |
| C | 20% |

### 推薦規則

將與現有購物清單相關的產品推薦給客戶，依據以下條件產生購買清單：

- 預算（Budget）。
- 購物袋最大承載重量（Capacity）。
- 客戶對各類產品的喜好度（Preference）。

**目標：在預算與承重限制內，讓客戶買到越多自己喜歡的產品。**

### 推薦結果範例

假設客戶預算為 **700 元**，購物袋最大承重為 **15 公斤**，演算法可能推薦：

| 產品 | 數量 | 小計價格 | 小計重量 | 類別 |
| --- | ---: | ---: | ---: | :---: |
| 產品 1 | 2 | 200 元 | 4 公斤 | A |
| 產品 4 | 1 | 300 元 | 4 公斤 | B |
| 產品 5 | 1 | 180 元 | 6 公斤 | C |
| **合計** | **4** | **680 元** | **14 公斤** | — |

這份清單符合預算與承重限制，也考慮了客戶的喜好度。透過基因演算法，根據現有購物清單與推薦規則尋找最佳推薦組合，以提高客戶的購買機率。
